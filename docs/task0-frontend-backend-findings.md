## P0(阻断级):后端无法编译 —— 旧项目路径残留

**现象**:
```
error: failed to run custom build command for `rustmcl v0.1.0`
failed to read plugin permissions: failed to read file
'/home/tortb/devlop/Runa/src-tauri/target/debug/build/tauri-ac4abc95e6adefb1/out/permissions/app/autogenerated/commands/app_hide.toml'
```
**根因**: 仓库由旧项目 `Runa` 复制/改名而来。`src-tauri/target/` 内的构建产物被 Cargo 指纹缓存,
其中 `tauri-*` 插件的权限清单 `out/permissions/...` 记录了**旧绝对路径** `/home/tortb/devlop/Runa`。
现在 `/home/tortb/devlop/Runa` 已不存在,但 `build.rs`(tauri_build)仍按缓存的旧路径去读权限文件 → 编译失败。
**这也直接解释了为什么"点了没反应 / 空壳"——后端从没构建成功,应用根本起不来或前端拿到的是最旧的坏产物。**
**修复**: 进入 `src-tauri` 后 `rm -rf target` 再重新 `cargo check`(已验证此操作后正常编译)。

## 登录门禁缺失(任务 1 的关键断点)

`launch.rs` 的 `resolve_launch_account` 在没有激活账号时**静默回退为离线 Steve + 随机 UUID**:
```rust
None => Ok(("Steve".into(), uuid::Uuid::new_v4().to_string(), "0".into())),
```
即"未登录也能启动"。且 `launch_instance` 是**先补资源、后解析账号**,若账号缺失,后端会先把资源全下载一遍,最后才报"没账号",体验极差。
Spec 要求:未登录点启动应被拦截并引导登录。
**修复(已做)**:
- 后端 `spawn_instance_launch` 在 `spawn` 之前前置校验激活账号,无则直接返回 `Err("未登录账号…")`,不再触发资源下载。
- 前端 `InstanceStore.launch` 在发起 invoke 前检查 `active`,未登录直接 `openLogin()`。
- 注:`launch_version`(下载页快速启动)按 Spec 仅对 `launch_instance` 加门禁,故下载页保留离线 Steve 快捷启动作为既有功能。
